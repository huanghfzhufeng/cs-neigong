# 第 12 章 · 总结与速查

把这块收个尾。主线再走一遍:架构是什么(组件 + 连接件 + 约束)与怎么描述(4+1 视图) 经典架构风格(数据流 / 调用返回 / 独立组件 / 数据共享 等) 三个形式化方法(DSSA / ABSD / ADL)。下面这张架构风格对比表,是案例答题时最该带在手边的。

**架构风格对比(案例必备)**

| 风格 | 机制 | 优点 | 缺点 | 例子 |
| --- | --- | --- | --- | --- |
| 管道-过滤器 | 数据流经过滤器变换 | 松耦合、可复用、易并行 | 不适合交互、有开销 | 编译器、Unix 管道 |
| 分层 | 每层调下层、服务上层 | 关注分离、可替换 | 性能损耗、层穿透 | OSI、Web 三层 |
| 事件驱动 | 发布事件、订阅响应 | 松耦合、易扩展 | 流程不直观、难调试 | GUI、消息队列 |
| 仓库/黑板 | 围绕共享数据协作 | 数据集中、易共享 | 中心成瓶颈/单点 | 符号表、数据库应用 |
| C/S、B/S | 客户端-服务器 | 职责清晰、B/S 易部署 | C/S 需安装维护 | 各类网络应用 |
| MVC | 模型/视图/控制器分离 | 关注分离、一模型多视图 | 复杂度增加 | Web 框架 |
| 微服务 | 独立小服务、去中心 | 独立部署、可扩展 | 分布式复杂度高 | 云原生系统 |

**形式化方法速查**

| 概念 | 一句话 |
| --- | --- |
| 架构三要素 | 组件(做什么)+ 连接件(怎么连)+ 约束(规则)。 |
| 4+1 视图 | 逻辑 / 开发 / 进程 / 物理 + 场景(贯穿验证)。 |
| DSSA | 领域参考架构;三活动:领域分析/设计/实现。 |
| ABSD | 架构驱动开发;三基础:功能分解/选风格/软件模板。 |
| ADL | 架构描述语言;三元素:组件/连接件/配置。 |
| 风格 vs 模式 | 风格是系统级整体组织,模式是局部细粒度方案。 |

**学习建议**

它和质量属性是黄金搭档:给一个场景,选合适的架构风格,并说明它的优缺点、以及如何支撑所需的质量属性(和上一份《质量属性与架构评估》连起来用)。建议把上面对比表里每种风格的「机制 + 优缺点 + 适用」讲清楚,再找真实场景练「给场景选风格 + 讲理由」。

质量属性定目标,架构风格给结构 —— 系统设计的两大支柱,到此齐了。
