# 第 13 章 · 总结与速查

把这门收个尾。主线再走一遍:概述与生命周期 开发模型 需求 设计(结构化 / 面向对象 / UML / 设计模式) 测试 维护与质量 项目管理 过程改进 配置管理与复用。软件工程的核心精神,始终是用「工程化的流程和方法」对抗「软件规模带来的复杂度」。

**核心考点速查**

| 概念 | 一句话 |
| --- | --- |
| 软件危机 | 规模变大后难管理 催生软件工程。 |
| 生命周期 | 可行性需求设计编码测试维护。 |
| 瀑布 vs 敏捷 | 线性文档驱动 vs 短迭代拥抱变化。 |
| 需求三类 | 功能 / 非功能 / 设计约束;核心产物 SRS。 |
| DFD | 画数据如何流动变换;不表示控制时序。 |
| 内聚 / 耦合 | 内聚越高越好、耦合越低越好。 |
| OO 三特性 | 封装 / 继承 / 多态。 |
| 类关系 | 依赖 < 关联 < 聚合 < 组合(强度递增)。 |
| UML 两类 | 结构图(静态)+ 行为图(动态)。 |
| 设计模式 | 创建型 / 结构型 / 行为型,共 23 种。 |
| SOLID | 五大原则;开闭原则是灵魂。 |
| 黑盒 / 白盒 | 看功能 vs 看代码逻辑。 |
| 测试层次 | 单元集成系统验收(V 模型)。 |
| 维护四类 | 改正 / 适应 / 完善(最多)/ 预防。 |
| 关键路径 | 最长路径,决定最短工期。 |
| CMMI | 五级:初始已管理已定义量化优化。 |

**学习建议**

这门概念多、对比多,纯靠死记容易乱。最好的办法是:先用本篇的图把各种「模型、图、原则、流程」的框架立起来,再用对比表把易混点(瀑布 vs 敏捷、聚合 vs 组合、黑盒 vs 白盒、内聚 vs 耦合、各种维护类型)一组组拎清楚,最后刷真题巩固。需求、设计、测试、UML 这几块在架构师的案例和论文里也常出现,值得认真过。

理解框架 + 拎清对比,软件工程就不再是一堆零散名词。
